## Incidente 01/05/2026 — TENTATIVA 2 (mesmo dia, reboot após incidente inicial)

### Causa
Após reboot, o sistema arrancou no kernel 6.17 (não 6.14), então o driver wl.ko compilado para 6.14 não estava disponível.

### Sintomas
- `lspci` mostra BCM4360, mas sem interface wlan/wlp
- `sudo modprobe b43` → "ERROR: FOUND UNSUPPORTED PHY (Analog 12, Type 11 (AC), Revision 1)" — b43 é antigo demais para AC
- `sudo modprobe brcmfmac` → driver carrega mas sem criar interface (firmware disponível só para SDIO, não PCI)
- DKMS build no 6.17 falha com erro crítico:

```
src/shared/linux_osl.c:23:10: fatal error: typedefs.h: Arquivo ou diretório inexistente
   23 | #include <typedefs.h>
compilation terminated.
```

### Solução
1. `dkms remove broadcom-sta/6.30.223.271 --all`
2. `dkms add broadcom-sta/6.30.223.271`
3. `dkms build -k 6.14.0-37-generic broadcom-sta/6.30.223.271` → OK
4. `dkms install -k 6.14.0-37-generic broadcom-sta/6.30.223.271` → "Module version exactly matches" (já estava compilado)
5. Boot no kernel 6.14 → `sudo modprobe wl` funciona

### Verificações após reboot no 6.14
```bash
lsmod | grep wl
ip link show type wifi
nmcli device
```

### Lição aprendida
- GRUB `saved_entry=1>2` pode não funcionar em reinícios normais (ignora saved_entry)
- Antes de reiniciar: confirmar que `cat /boot/grub/grubenv | grep saved_entry` mostra 6.14
- Ou: boot manual pelo menu GRUB "Advanced options for Ubuntu" → 6.14
